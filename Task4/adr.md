### Название задачи
Доступ депозитных ставок в оба кол-центра (in-house + партнёр)

### Автор
Илья, цифровая трансформация

### Дата
2025-08-09

---

## Функциональные требования (Use Cases)

| № | Актёры / системы | UC | Описание |
|:-:|:-|:-|:-|
| RUC-1 | Сервис депозитов → Система КЦ | Рассылка актуальных ставок | Каждые 15 мин публикует JSON-сообщение со всеми ставками. |
| RUC-2 | Система КЦ | Чтение ставок | Кэширует полученный JSON, показывает оператору при входящем звонке. |
| RUC-3 | Сервис депозитов → SFTP-шлюз | Экспорт ставок партнёру | 1 раз в час кладёт CSV-файл в выделенную SFTP-папку. |
| RUC-4 | Партнёр КЦ → SFTP | Забор файла | По расписанию (каждый час + ручной триггер) скачивает файл, отображает ставки в своём UI. |

## Нефункциональные требования

| № | Требование |
|:-:|:-|
| NFR-1 | Актуальность ставок ≤ 15 мин внутр. КЦ; ≤ 1 ч партнёр. |
| NFR-2 | Формат CSV для внешнего файла; UTF-8, «;» разделитель. |
| NFR-3 | Канал SFTP шифруется (TLS 1.3) + IP-white-list. |
| NFR-4 | JSON-сообщения доставляются «at-least-once», допускается дубликат. |
| NFR-5 | Решение не нагружает АБС → ставки берутся из Rate DB. |

---

## Решение

### C4-Context
*См. диаграмму «Context – Rates MVP»*

* Новые внешние взаимодействия:
    * **Deposit Service → Kafka-topic `rates.updates` → Система КЦ**
    * **Deposit Service → SFTP (CSV) → Партнёр КЦ**

### C4-Component (внутри Deposit Service)

| Компонент | Ответственность |
|-----------|-----------------|
| RatesFacade (REST) | CRUD ставок (админ-UI). |
| RatesPublisher | Каждые 15 мин сравнивает `Rate DB` → пуш JSON в Kafka. |
| CsvExporter | Каждые 60 мин генерирует `rates_YYYYMMDD_HH.csv`, кладёт в SFTP. |

**Техстек**

* Kafka (уже есть в архитектуре).
* Spring Batch (экспортер).
* JSCH / WinSCP cli для SFTP.

### Почему так
* Kafka = zero-copy до КЦ, не трогаем АБС.
* SFTP удовлетворяет ограничение «только файлы».
* Всё пишется внутри уже существующего Deposit Service ⇒ минимум новых сервисов.

## Альтернативы

| Вариант | Почему отказались |
|---------|------------------|
| 1. REST-API от Deposit Service к партнёру | партнёр не может принимать API. |
| 2. Прямая выгрузка из Excel в SFTP | Excel → ручная, потеряем аудит и версионирование. |

---

## Риски

* Потенциальный «снежный ком» CSV-файлов, если партнёр долго не забирает. Решение — retention 7 дней + cron-cleaner.
* Отставание Kafka-консьюмера КЦ → оператор увидит старую ставку. Смягчаем local-cache TTL 15 мин + подсветка «может измениться».
