## Решение

### Диаграмма контекста
*Файл*: `task3_c4.drawio` → вкладка **C4-Context**.  
Показывает основные актёры (клиент, менеджеры), фронтовые каналы (сайт, ИБ) и корневые системы (Сервис депозитов, КЦ-система, АБС, SMS-шлюз).

### Диаграмма контейнеров
*Файл*: `task3_c4.drawio` → вкладка **C4-Container**.  
Детализирует два легаси-монолита:

* **Интернет-банк (legacy .NET 4.5)** — остаётся в своём пуле, но взаимодействует через **API Gateway**.
* **АБС (Delphi + Oracle)** — доступ только через **Deposit Service** (SOAP/adapter).

Новые контейнеры:

| Контейнер             | Назначение                                           | Технологии       |
|-----------------------|------------------------------------------------------|------------------|
| **Web-App**           | SPA для сайта (список депозитов, форма заявки)       | React            |
| **API Gateway**       | Авторизация, маршрутизация REST/gRPC                 | .NET 8 YARP      |
| **Deposit Service**   | Логика заявок, расчёт ставки, интеграция с АБС и SMS | Java Spring Boot |
| **Rate DB (MS SQL)**  | Хранит справочник ставок + историю                   | MS SQL           |
| **Event Bus (Kafka)** | Асинхронная интеграция, буферизация заявок           | Kafka            |

**Почему так**

* Убираем прямой SQL ИБ → Oracle, всю логику держим в `Deposit Service`.
* Kafka гасит всплески заявок и защищает АБС (вертикально) от перегрузки.
* API Gateway позволяет позднее мигрировать ИБ на микросервисы, оставаясь единым фасадом.
* Ставки из Excel импортируются в `Rate DB` через back-office UI; кредиты-отдел имеет read-only доступ.

## Альтернативы

1. **Прямой REST от ИБ к АБС**  
   *+ проще реализация, − ломаем изоляцию, нагрузка на АБС, дублирование логики.*
2. **Использовать существующий SMS-модуль ядра**  
   *− нужна доработка подрядчика, сроки + риски.*

Отказались, так как противоречат NFR-4 и срокам MVP.

---

## Недостатки, ограничения, риски

* АБС масштабируется только вертикально → при взлёте онлайн-канала понадобится быстрый offload / кэш.
* Kafka не поддерживается «как есть» в старом ИБ, придётся держать мост REST → Kafka.
* Сервис депозитов — новый стек; нужен DevOps-пайплайн и наблюдаемость (отдельная работа).
